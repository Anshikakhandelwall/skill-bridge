1. Product vision
SkillBridge AI is a Career GPS with a living “Career Twin.”
Instead of giving generic course recommendations, it maintains a structured, evolving model of each student:
What they can demonstrate—not merely claim
The target role and current market-aligned competency map
Their available time, academic load, interests, and momentum
The shortest credible path to becoming interview-ready
Its key differentiator: every recommendation is connected to an outcome. A project, lesson, mock interview, or assessment updates the Career Twin and causes the roadmap to re-route—like Google Maps responding to traffic.
Core promise: “Tell SkillBridge where you are and where you want to go. It will tell you the next best move, explain why, and adapt when life changes.”
2. Five judge-worthy innovations
Career Twin + evidence-based skill graph
Skills are represented as claimed, inferred, assessed, and demonstrated. A GitHub project or passed assessment carries more weight than a self-reported skill.

Dynamic roadmap re-routing
If a student fails a DSA assessment, loses study hours during exams, or becomes interested in AI, the system recalculates the plan while preserving progress already earned.

Career Path Simulator
Let students compare scenarios:
“What happens if I pursue frontend vs data analyst?”
“Can I be internship-ready in 12 weeks at 6 hours/week?”
The product shows trade-offs, confidence, and realistic milestones.

Project-to-proof engine
Rather than saying “learn React,” it recommends a portfolio project tailored to the target role and skill gaps, with acceptance criteria that turn work into resume-ready proof.

Explainable AI decisions
Every roadmap item includes: “Why this now,” “What it unlocks,” “Estimated effort,” and “Evidence that proves completion.” This makes the AI trustworthy and visibly useful.

3. Complete user journey
First login
The student signs in with Google/GitHub. The landing experience asks one simple question:
“What role do you want to be ready for next?”

They can choose a role, browse paths, or select “Help me explore.”
Profile creation
A short, progressive form captures:
Education, graduation date, and location
Current skills and comfort level
Interests
Weekly hours available
Academic workload level
Career target and deadline
GitHub username and resume upload
Avoid asking everything at once. Collect high-value inputs first, then enrich the profile later.
Resume and GitHub analysis
The Resume Analyst extracts:
Skills, tools, projects, education, experience
Strong evidence versus vague claims
Missing impact statements
Candidate target roles
Resume improvement opportunities
GitHub analysis can identify languages, repositories, activity, README quality, deployment links, and project complexity.
The student sees a clear output:
“You have evidence of Python and SQL. You claim React, but there is no project evidence yet.”

Goal selection
The student selects:
Target role: e.g., Frontend Engineer
Target date: e.g., internship applications in 16 weeks
Weekly capacity: e.g., 8 hours
Preferred learning style: build, read, video, practice
Constraints: exams, college schedule, part-time work
AI roadmap generation
The Career Planner creates a roadmap with:
Baseline assessment
Skill-gap matrix
Milestones
Weekly goals
Projects
Interview preparation checkpoints
Confidence score toward the target role
Example:
Goal: Frontend internship in 16 weeks
Current readiness: 34%
Primary gaps: React state management, testing, deployment, DSA fundamentals

Weeks 1–3: React foundations + component project
Weeks 4–6: API integration + testing
Weeks 7–10: Portfolio project with deployment
Weeks 11–13: DSA and behavioral stories
Weeks 14–16: Mock interviews + applications
Weekly progress
Each week, the student has a focused “Next Best Week” view:
Three to five tasks maximum
Estimated time for each task
A project checkpoint
One short assessment
One reflection prompt: “What felt difficult this week?”
The student marks tasks complete, submits a GitHub link, or records blockers.
Continuous adaptation
SkillBridge reacts to events:
Task completed: unlocks the next skill or project milestone
Assessment failed: inserts remediation and reduces difficulty
New interest: offers a route comparison before changing direction
Exam week: compresses the plan into maintenance mode
More time available: pulls forward higher-impact work
Project submitted: updates demonstrated skills and readiness
The product should explicitly show the change:
“Your plan changed: we moved testing to next week because your React assessment exposed an API-state gap.”

4. Multi-agent AI architecture
Use a central Career Orchestrator. The five “agents” should be specialized workflows sharing structured state—not independent chatbots passing unstructured prose.
```mermaid
flowchart LR
    U["Student"] --> A["Next.js App"]
    A --> O["Career Orchestrator"]

    O --> R["Resume Analyst"]
    O --> C["Career Planner"]
    O --> P["Project Coach"]
    O --> M["Mentor"]
    O --> I["Interview Agent"]

    R --> S[("Career Twin / Student State")]
    C --> S
    P --> S
    M --> S
    I --> S

    S --> E["Event Log"]
    E --> O
```



Agent	Responsibility	Inputs	Outputs
Career Planner	Creates and re-routes the end-to-end career roadmap	Target role, skill graph, deadline, hours, constraints	Milestones, weekly plan, readiness score, rationale
Resume Analyst	Converts resume/GitHub data into evidence-based signals	Resume text, GitHub metadata, profile	Extracted skills, evidence confidence, resume improvements
Mentor Agent	Provides contextual guidance and handles blockers	Current week, progress, reflection, roadmap	Next action, encouragement, explanation, blocker resolution
Interview Agent	Runs role-specific practice and evaluates answers	Target role, completed skills, interview history	Questions, rubric scores, feedback, weak-area tasks
Project Coach	Turns skill gaps into portfolio-worthy proof	Missing skills, interests, repository status	Project brief, milestones, rubric, README/resume bullet suggestions

How the agents communicate
Use a shared canonical object called the Career Twin, stored in PostgreSQL/Supabase. Each agent receives only the relevant slice of the student’s data and returns JSON matching a strict schema.
Example event:
{
  "event_type": "assessment.completed",
  "student_id": "stu_123",
  "skill": "react_state_management",
  "score": 42,
  "passed": false,
  "occurred_at": "2026-07-18T10:00:00Z"
}
The orchestrator then:
Updates the skill evidence score.
Calls the Career Planner.
Replaces only impacted roadmap tasks.
Creates a visible roadmap.changed event.
Uses the Mentor Agent to explain the change in plain language.
Shared information
All agents can access appropriate portions of:
Student profile and constraints
Skill graph and evidence scores
Target role competency map
Roadmap and task history
Assessment results
GitHub/resume-derived evidence
Project progress
Interview scores
Adaptation/event history
Do not let agents overwrite each other freely. The orchestrator validates agent outputs and applies controlled updates.

8. Making GPT-5.6 the product engine, not a chatbot
The key principle: GPT should make structured decisions that change product state.
Use GPT-5.6 for:
Extracting a normalized skill graph from resume and GitHub evidence
Mapping a student’s profile to a role competency framework
Generating roadmap objects in validated JSON
Selecting the next best task based on deadlines, scores, and available time
Explaining adaptations in human language
Producing tailored project briefs and rubrics
Running interview simulations and turning feedback into new roadmap tasks
Summarizing weekly progress and identifying risk of dropout
Example structured roadmap output:
{
  "readiness_score": 34,
  "top_gaps": ["react_state_management", "testing", "deployment"],
  "weekly_plan": [
    {
      "week": 1,
      "estimated_hours": 8,
      "tasks": [
        {
          "title": "Build a React expense tracker",
          "skill": "react_state_management",
          "evidence_required": "GitHub URL and deployed app"
        }
      ]
    }
  ],
  "rationale": "React state is a prerequisite for the recommended portfolio project."
}
Keep the model behind tool-like boundaries:
get_student_career_twin
get_role_competencies
save_roadmap
create_tasks
record_skill_evidence
create_adaptation_event
This gives you a compelling agentic story: the model reasons, calls trusted application functions, and produces auditable changes. GPT-5.6 supports structured outputs and function calling, which makes this architecture practical. OpenAI GPT-5.6 Sol documentation
9. Using Codex during development
Use Codex as your fast, disciplined engineering partner—not just for autocomplete.
Have it help you:
Scaffold the Next.js + Supabase architecture
Generate database migrations and typed data models
Create Zod schemas for every AI response
Build the dashboard and polished reusable UI components
Implement OpenAI orchestration functions
Review security: API key isolation, Supabase RLS, upload validation
Generate seed data for a strong demo persona
Write tests for roadmap adaptation logic
Debug deployment issues and run final code review
Give Codex project-level instructions such as:
Use TypeScript strictly.
All AI outputs must validate with Zod before persistence.
Never expose OpenAI or Supabase service keys to the browser.
Use Supabase RLS for every user-owned table.
Prefer small reusable components and accessible UI.
For the demo, Codex is especially valuable for building a complete vertical slice quickly: onboarding → analysis → roadmap → task completion → automatic re-route.

“Students don’t need another course catalog. They need a system that knows where they are, where they want to go, and what they should do next. That’s SkillBridge AI: Google Maps for careers.”

0:00–0:25 — The student problem
“Meet Aisha, a second-year student who wants a frontend internship in four months. She has a resume, knows some HTML and Python, and has eight hours a week. But she doesn’t know the shortest credible path to becoming employable.”

0:25–0:50 — Create the Career Twin
“Aisha uploads her resume and connects GitHub. SkillBridge does not simply list claimed skills. It creates an evidence-based Career Twin. It recognizes Python and HTML as demonstrated, identifies React as a claimed—but not yet proven—skill, and spots missing portfolio evidence.”

Show the skill evidence panel.
0:50–1:25 — Generate the plan
“Aisha selects ‘Frontend Engineer’ and says she has eight hours a week. The Career Planner compares her current skill graph against the role requirements and builds a 16-week roadmap: React foundations, API integration, testing, a deployed portfolio project, and interview preparation.”

Show roadmap and readiness score.
“Every task says why it matters, what it unlocks, and what proof Aisha needs to produce.”

1:25–2:05 — Show dynamic adaptation
“This is where SkillBridge becomes a Career Operating System. Aisha takes a React assessment and struggles with state management.”

Submit a pre-seeded failed assessment.
“Instead of telling her to work harder, the system updates her demonstrated skill score, inserts a focused remediation project, shifts testing by one week, and explains the decision.”

Show the roadmap change notice.
“This is career navigation, not generic advice.”

2:05–2:35 — Show proof-building
“The Project Coach now proposes a portfolio-ready expense tracker with API integration, deployment requirements, and resume-ready impact bullets. Progress on that project becomes verified evidence in Aisha’s Career Twin.”

Show project brief and GitHub evidence placeholder.
2:35–3:00 — Close
“SkillBridge AI turns scattered learning into an adaptive path toward employability. It combines resume intelligence, project coaching, mentorship, interview practice, and continuous planning into one system that learns with the student.”

“We are not building another chatbot for career advice. We are building the operating system for a student’s career.”
